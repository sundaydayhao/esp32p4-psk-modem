# AP580 2.4 kbps：P4 发射端检查

## 结论与范围

本次链路为电脑音频 → AP580 → P4 UART1 → P4 ES8311 → 音频线 → HPM6750 → AP580 → 耳机。

**P4 到 HPM 的 PSK 音频发射已通过一个已知文本窗口检查；完整语音链路尚未通过。** 两轮语音测量中，P4 UART 原始输入字节、有效语音帧、调制器消费包数均为 0。电脑持续播放是用户确认的状态，不能据此认定 AP580 已经输出串口数据。

仅修改、构建及烧录 P4。HPM6750 只通过 COM23 调整运行参数，未修改代码或烧录；检查时 HPM 工作区干净，HEAD 为 `c84c683eb9e282c3ff7c819623f7a4f1d4078abb`。

## 接线与配置

| 项目 | 当前配置 |
| --- | --- |
| P4 USB 控制口 | COM21，115200 |
| HPM USB 控制口 | COM23，115200 |
| P4 AP580 UART | UART1，115200 / 8N1，无流控 |
| P4 TX | GPIO32 → AP580 RX；J1 物理第 26 脚 |
| P4 RX | GPIO33 ← AP580 TX；J1 物理第 29 脚 |
| 地 | 两模块与对应主板共地 |
| AP580 编码档位 | 两端均为 2400 bit/s |
| PSK | 2x8PSK1200F，中心 2000 Hz |
| P4 音频输出 | `OUTVOL 70 60`；实际驱动应用第二个参数 60 |
| HPM 接收参数 | input=2、ADC=195、analog=11、AGC=0、lane=AUTO |
| HPM CRC 策略 | `APRECOVERY 0`，严格丢弃 CRC 错包 |

GPIO 编号不是排针顺序编号。`APRATE 2400` 仅改变软件封包和播放时序，不改变 AP580 硬件档位。

AP580 手册 `C:/projects/hpm6750-psk-modem/docs/AP580/AP580_CH(3.0).pdf` 第 12 页列出上电采样的模式引脚：正常 2.4 kbps 为 MODE_SEL=000，UART 115200 为 BR_SEL=00。第 16 页注明编码器默认启用、VAD 默认关闭。因此，默认正常模式不需要额外发送“开始编码”命令；若改过跳线，应重启模块使引脚模式生效。第 15–16 页另有软件配置命令，本次没有向模块发送此类命令。

## P4 固件改动

- `sdkconfig` 和 `sdkconfig.defaults` 启用确认的 GPIO32/33 UART 接线，默认编码档位 2400。
- `RXDIAG` 和网页状态 API 增加 UART 原始字节、同步丢弃、非语音记录及发送包统计。
- `tx_packets/tx_bytes` 表示整个包已被调制器取走，不表示 DAC 已播放完毕；`pending` 仅为待取包队列长度，不含正在调制的包。
- 启动仍为 Text/RX；切换到 Audio/TX 才发送模块输入。没有有效语音输入时不启动语音调制。

IDF 5.5.5 构建成功，COM21 烧录成功并校验 Flash。应用大小 1536304 B；应用 SHA-256：

```text
21890bb7091794499299aba0491bd78617c52ebd289304fd320a7f64843b509b
```

`tools/run_content_checks.ps1` 通过图片 CRC/修复、AP580 三档封包、PSK 二进制回环及 UART 播放时序测试。其中 2400 档理想信道回环含 144 个不同 AP580 帧、2304 B，完整一致。这是软件回归，不是实物语音结论。

## 实物记录

### 已知文本发射

P4 重复发送以下 ASCII 字符串，HPM 使用 Text/RX 和 `LOG TEXT`：

```text
[BEGIN-P4TX]ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789-ESP32P4-TRANSMIT-CHECK-9876543210[END-P4TX]
```

使用 `TX <上述字符串>` 设置原文（`TXTEXT` 是预设选择命令，不能用于任意原文）。P4 开始发射后预热 10 秒，随后采集 30 秒。剔除明确标识的 `[diag]` / `[carrier]` 日志及串口实际 CR/LF 后，对整个接收窗口按循环原文对齐校验，保留开头和末尾的不完整帧。

| 指标 | 结果 |
| --- | ---: |
| 窗口文本字节 | 16958 |
| 完整测试帧 | 184 |
| 完整帧一致 | 184 |
| 全窗口差异字节 | 0 |

该窗口证明此电平下的 P4 文本调制输出和音频线路可用。Text 使用 Varicode，Audio 使用原始二进制，因此不能用文本成功替代 Audio 实物验证，也不能外推为永久零误码。

## 输入恢复后的复测

确认 AP580 TX 接 P4 丝印 33、RX 接丝印 32，模块供电且共地；确认模块正常编码模式和 115200 波特率。修改跳线后重启模块，再运行：

```powershell
& C:/Espressif/tools/python/v5.5.5/venv/Scripts/python.exe -u tools/p4_ap580_tx_check.py --seconds 120 --warmup 20 --volume 60 --label live-2400
```

脚本自动设置 P4 Audio/TX、HPM Audio/RX，记录计数差和日志，结束后停止 P4 发射。显式加 `--keep-tx` 可在测量完成后保持发送以便耳机试听。脚本不会构建或烧录任一板。

2.4 kbps 每 22.5 ms 输出一个 16 B UART 帧，约 44.4 帧/s、711 B/s；本项目六帧组一个 PSK 包。检查应看到 P4 原始字节、有效帧和发送包持续增长，HPM 有效帧和 UART 转发持续增长，CRC、队列丢弃等错误计数不增长。

两块板的快照非同时采集，包和 UART 播放存在流水线延迟，脚本容忍 24 帧计数差；这是计数级链路检查，不是逐位载荷比对或声音质量评价。当前 HPM STATUS 未提供 `rxdrop` 时，报告显式列为不可用。最终耳机是否连续可懂仍需要现场试听。
